# Motion storyboard — Alshorouk homepage

_As-built record, 2026-10-11. Spec §8.4 (six signature motion moments), §8.6 (safeguards) and §8.7 (storyboard fields for each homepage scene)._

**How this document was produced.** The scenes were coded before this storyboard was written, so it records what the code does rather than a plan approved in advance (a process deviation, noted on the task board as P2-04). Four agents extracted the facts from the source: components, CSS keyframes, GSAP timelines and ScrollTrigger settings. Four separate verifier agents then re-checked every value against the source and the screenshots, and corrected 98 items (listed in the appendix). Durations, eases and triggers therefore come from the code; screenshots confirm settled states only.

The verification also found two motion defects that no test had caught. Both were fixed on 2026-10-11 and are described here in their fixed form:

- **Hero photo parallax rendered 0 px.** The tween targeted an element whose CSS intro animation owns `transform`.
- **The reading-progress bar on segment pages and articles was always 0 px wide.** Tailwind 4's `scale-x-0` compiles to the CSS `scale` property, which multiplied the bar's `transform: scaleX(p)` back to zero.

## Motion system shared by every scene

- **Stack.** GSAP 3.15 with ScrollTrigger and DrawSVGPlugin through `@gsap/react` (`useGSAP`), registered once in `src/lib/motion/gsap.ts`: defaults `power3.out` / 0.7 s, `ScrollTrigger.config({ ignoreMobileResize: true })`. There is no Lenis, no ScrollSmoother and no GSAP pinning. The only "pins" are CSS `position: sticky` (Scene 4 media frame, the Values heading at xl, the FAQ heading column) and the fixed compact header bar.
- **First-paint intros** (home hero and inner-page heroes) are pure CSS keyframes: `als-rise`, `als-fade-up`, `als-sunrise-mask`, `als-zoom-settle`, `als-draw` and `als-cue`. They are gated only by `prefers-reduced-motion: no-preference`, so they need no JavaScript.
- **Declarative reveals** (`[data-reveal]`). CSS hides an element only under `html.reveal:not(.motion-off)` and no-preference. `MotionRuntime` adds `html.reveal` after hydration, and only after marking everything already in the viewport as revealed, so first-screen content is never hidden. It then reveals the rest with `ScrollTrigger.batch` (start `top 90%`, once, GSAP 3.15's 0.016 s batch window):

  | Type | Hidden state | Reveal |
  |---|---|---|
  | `up` | opacity 0, `translateY(1.25rem)` | 0.65 s `power3.out`; stagger `min(0.08, 0.48/(n−1))` s |
  | `lines` | each `.mask-line > span` at `translateY(170%)` inside a padded mask (Arabic dots and diacritics are not clipped) | 0.8 s `expo.out`, 0.08 s per line |
  | `image` | `clip-path: inset(100% 0 0 0)` | 1.0 s `expo.inOut`, stagger 0.12 s |
  | `fade` | opacity 0 | 0.8 s `power2.out` |

- **Tokens** (`src/lib/motion/tokens.ts`):
  - `mq.motion` = no-preference;
  - `mq.desktopMotion` = no-preference and min-width 64rem and `pointer: fine`;
  - `mq.mobileMotion` = no-preference and max-width 63.98rem;
  - `motionDisabled()` = `html.motion-off`, reduced motion or Save-Data.

  CSS eases: `--ease-sunrise` `cubic-bezier(0.16,1,0.3,1)`, `--ease-flow` `cubic-bezier(0.65,0,0.35,1)`, `--ease-soft` `cubic-bezier(0.33,1,0.68,1)`.
- **Fail-safes.** If the motion runtime never starts, `html.reveal` is never added, so nothing is hidden. The inline boot script also adds `html.motion-off` after 3.5 s if the runtime has not started, which turns off motion-dependent styling such as the About hero's monochrome layer. If trigger registration throws, content is marked revealed. Reaching the end of the page reveals anything left. Nodes added later are registered after 900 ms.

## Safeguards (spec §8.6)

| Safeguard | As built |
|---|---|
| Honour `prefers-reduced-motion` immediately; show all content; no parallax, pinning or count-up | Hidden states and intros exist only under no-preference. A global reduce rule clamps CSS animations and transitions to 0.01 ms. Every JS scene returns at `motionDisabled()`, and `gsap.matchMedia` reverts its tweens if the preference changes mid-visit. Verified by `tests/e2e/keyboard-motion.spec.ts` (every reveal in its final state under reduce) and the reduced-motion axe scans (0 violations). |
| Visibility change, backgrounding, resize, unmount; no duplicate triggers | GSAP's ticker runs on `requestAnimationFrame`, which browsers pause in background tabs (no custom `visibilitychange` code). On resize, ScrollTrigger refreshes itself (mobile URL-bar resizes ignored) and `matchMedia` rebuilds at breakpoints. On unmount every scene reverts its `gsap.context`, and `MotionRuntime` kills its triggers and is keyed on the pathname, so client navigation does not duplicate them. |
| No JS-induced layout shift | Motion uses `transform`, `opacity`, `clip-path` and `stroke-dashoffset`; image boxes are reserved. CLS was 0 in every Lighthouse run. |
| No looping first-load explosion; coarse pointer, Save-Data | No infinite loops: the hero scroll cue plays twice and stops at ≈ 6.6 s. Scroll-linked desktop effects need a fine pointer. Save-Data turns JS motion off. Not done: `deviceMemory` / `hardwareConcurrency` checks. |
| Keyboard users never reach off-screen pinned elements | No GSAP pinning; sticky elements stay in the flow; focus order follows the DOM (keyboard and axe tests). |

## Known limits

- The hero timeline overlaps more than the spec's sequence. The headline starts at 0.08 s, earlier on purpose for LCP, and the curve finishes at 2.03 s.
- Moment 2 uses one trigger per figure. A reader who stops scrolling between a column's reveal and its counter trigger can briefly see the counter's start value; the qualifier and the final value are always in the accessible name.
- Scroll-linked effects need a fine pointer at ≥ 1024 px, so touch tablets in landscape get the declarative reveals only.
- ScrollTrigger is registered on every page, also under reduced motion, which keeps a ≈ 60 Hz `requestAnimationFrame` keep-alive at idle (PERF-3, open in `docs/open-items.md`).
- Save-Data disables JS motion but not the CSS first-paint intros (finite transform/opacity animations).
- First-screen content is never hidden. The reveal states (`html.reveal`) switch on only after hydration, once everything already in view is marked revealed, so there is no flash and no LCP delay. Trade-off: first-screen `[data-reveal]` content has no entrance animation on a full page load (it still animates after client navigations and as content scrolls in). If JavaScript fails, nothing is hidden.
- Switching language is a full page load, by design: a client-side switch re-mounted the whole document anyway.
